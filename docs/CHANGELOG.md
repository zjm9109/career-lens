# career-lens 变更记录

## 2026-08（v0.3 强化：语义四维 · 猎聘稳态 · 需求覆盖）

相对 v0.3 初版，本轮在「能跑通」之上补齐匹配可信度与三平台可用性。

### 2026-08-04 提交摘要（相对 `a82a5f0`）

| 主题 | 要点 |
|------|------|
| 运行稳态 | 暂停约 10s 自动恢复；猎聘短信/关不掉详情须手动继续；失败详情/页脚噪声不入库 |
| 推荐可信度 | 有 Key 无模型正文不得「建议投递」；LLM 503 等退避重试 |
| 投递列表 | xlsx 冻结表头+列宽；匹配度→契合→入列时间倒序；满 100 汰最低分最旧；侧栏「建议·匹配」合并列 |
| 降风控 | 标题跨域/列表避雷跳过开详情；5/8–12 条节奏；日风控≥3、猎聘开详情≥25 软锁；使用须知 |
| 规则收紧 | 信息化近义、软缺口不挡建议、待复核门槛与域压分前分等（见下方各节） |

### 已增加

#### 1. 契合四维 + 语义/向量（替代旧五维主路径）

| 维度 | 默认权重 | 含义 |
|------|----------|------|
| 角色契合 | 25 | 岗位角色是否同类 |
| 领域契合 | 30 | 行业/业务场景是否同域 |
| 能力契合 | 30 | 方法、工具、技能覆盖 |
| 资质条件 | 15 | 证书/年限/语言等（硬项仍先走门禁） |

- 有 API Key：OpenAI / 通义优先 **embedding 余弦**；DeepSeek 等走 **LLM JSON 四维**  
- 无 Key：规则映射 + 职业包域词仅作兜底  
- 职业包（`packs/*.js`）降级为：**适合岗位展示 + 无 Key 域兜底**，不再「一个岗位一个大 JSON」  
- 旧五维权重自动迁移到四维  

#### 2. 需求覆盖更贴近真实 JD

- **或选句**：`精通 ERP、OA、CRM 等至少一种` / `熟悉 Java 或 Python` → 一个需求单元，命中任一即满足  
- **匹配度**：按需求单元覆盖率（已满足 / 全部单元），不是字面词全中  
- **PM 过程隐含**：有项目经理 / PMP / 项目管理背景时，评审会、资料归档、交付复盘、会议纪要等视为已覆盖  
- **福利标签**：五险一金、年终奖等不再当必备能力缺口  
- **JD 具体度**：空泛套话岗降分封顶，防虚高  

#### 3. 猎聘可用性

- 识别分页（约 15–20 条/页），本页结束可 **CL_NEXT_PAGE** 翻页  
- 放慢开详情节奏（约 8–14s/条、每 8 条休息），降低「账号行为异常」  
- 详情进 `safe.liepin.com` / 短信验证 → **立即暂停**  
- 修正详情采集：须等到「职位介绍」就绪；避免顶栏壳、猜你喜欢串台（公司/薪资）  

#### 4. 本地存储

- 断点重复写入完整 JD 易触发 `Resource::kQuotaBytes quota exceeded`  
- 已加 `unlimitedStorage`，并对 runState / listSession / 投递列表 **压缩存盘**（去重、截断长文）  
- 仍满：侧栏「从头」或扩展管理页清除本扩展数据  

#### 5. 其它已有能力（v0.3 基线，本轮文档对齐）

- 硬门槛门禁（证书/语言/年限；UNKNOWN→FAIL）+ 封顶分  
- 待复核（防漏）：高契合被压分仍可 AI、可进投递列表  
- 规则侧写 + 可选 AI 侧写；投递列表导出 CSV

### 2026-08-04 续：Boss 导出复盘后的规则收紧

针对「高契合却几乎全进谨慎、待复核为空」：

- **近义/隐含**：信息化↔数字化/央企交付；国企↔央企；瀑布/敏捷/成本管控/实施交付在有 PM 背景时视为覆盖  
- **软缺口不挡建议**：上述类缺口进 `softGaps`，不再因字面未写强制「谨慎」  
- **或选抽取收紧**：拒收「缺少流程/建立秩序」类软句；只保留短工具词（ERP/OA/Java…）  
- **待复核**：门槛降至 60，并用域压分前契合分；角色高+能力尚可的跨域近邻可进待复核  
- **域门禁去重**：领域已 FAIL 时不再叠「必备：汽车」等同行业缺口  

### 2026-08-04 续：运行稳态与推荐可信度

针对「详情网络失败仍打分建议投递」「DeepSeek 忙线后规则满分建议投递」「暂停后不自动继续」：

#### A. 暂停自动恢复（`sidepanel/app.js`）

- 系统暂停（切页 / 验证码 / 网络异常 / 详情超时）后，**约每 10 秒**探测列表是否可读；恢复则自动继续**当前条**  
- **手动暂停**不自动恢复，需点「继续运行」  
- Boss / 猎聘识别「网络异常 / 加载失败」类页面并进入可自动恢复的暂停  

#### B. 拒绝失败详情入库（`boss/content.js`、`job-sections.js`）

- 识别「数据加载失败 / 点击重新加载 / 求职工具 VIP / 热门职位+热门城市」及大量「xx招聘」页脚 SEO 云  
- 此类正文**不打分、不入库建议**；抛错暂停并自动重试（需刷新列表/详情）  
- 页脚裁切：失败页正文极短时也会裁掉「求职工具/热门职位」（不再要求标记出现在第 40/80 字之后）  

#### C. 推荐状态不可信 → 待复核（`recommend.js`、`llm.js`）

- 已配置 API Key 且达到分析阈值时：**必须有模型分析正文**，才允许「建议投递」  
- **不限于 503**：网络失败、空响应、语义降级后的规则虚高（如四维全 100·rule）一律改 **待复核**  
- LLM 瞬时错误自动退避重试（约 3s / 8s / 15s，最多 3 次）  
- 无 Key 的纯规则模式不受影响；导出标明「推荐状态不可信 / 勿信规则虚高分」  

### 2026-08-04：投递列表导出 xlsx

- 「导出 Excel」改为真正的 **xlsx**（不再是 CSV）  
- **冻结首行**表头；列宽按内容估算自适应  
- 排序：**展示匹配度 ↓ → 契合原分 ↓ → 入列时间 ↓**（侧栏列表与导出一致）  
- 侧栏列「建议·匹配」：建议分组与匹配度/契合原分合并展示  

### 2026-08-04：投递列表满员淘汰

- 最多 100 条；第 101 条入库时替换 **匹配度最低 → 契合原分最低 → 入列时间最远** 的一条  
- 侧栏日志会提示被替换的岗位  

### 2026-08-04：猎聘短信风控不再自动死循环

- 「账号行为异常 / 短信验证」时列表页往往仍可读，**禁止**靠列表探测自动继续  
- 须在浏览器完成验证后点「继续运行」；避免同一条详情被反复打开  
- **无法关闭详情标签**时同样暂停，须手动关标签后点继续  
- **降触发**：列表已能命中避雷则**不开详情**；开详情间隔约 12–20s；每 5 条休息 75s；风控验证后冷却 90s  

### 2026-08-04：跨域跳过 · 随机节奏 · 日限额 · 使用须知

- **标题强跨域**（芯片/电力/医院/马拉松/土建等，且无信息化等软化词）→ **已排除**，三平台均跳过开详情  
- 每开详情 **5** 次额外休息 1–3s；每随机 **8–12** 次做人味操作（滚动/停顿/探列表）  
- **今日风控 ≥3** 或猎聘开详情 ≥25 → 精筛软锁至明天（清扩展数据会重置，请勿故意规避）  
- 首次精筛须勾选 **使用须知**；默认本批条数改为 5  

### 后续优化方向

| 优先级 | 方向 | 说明 |
|--------|------|------|
| 高 | 评测集固化 | 热力建造师、压裂英语、AI 漫剧、汽车悬架 PM、空岗套话、信息化近义等固定样例 |
| 高 | 猎聘稳态再收敛 | 可配置条间隔；风控后一键续跑提示；列表指纹与翻页游标更稳 |
| 高 | 语义成本与缓存 | 同 JD 向量/四维结果短期缓存；批量时少重复调模型 |
| 中 | 本地 embedding | 可选小模型/本地向量，降低对云端 Key 依赖 |
| 中 | 断言证据链 UI | 侧栏逐条对照 JD 句 ↔ 简历证据 |
| 中 | 稀疏 JD / 中性维 | 继续收紧「无要求→中性高分」 |
| 中 | UNKNOWN 策略设置 | 严/松可配（当前固定严） |
| 低 | 更多职业包展示 | 工程现场、销售等：仍以展示+无 Key 兜底为主，不堆大 JSON |
| 低 | 侧写版本号 | 「基于旧侧写」标记，避免画像与侧写漂移 |
| 低 | 职业包外置 | 可订阅/用户自建包（非写死仓库） |

原则不变：**门禁看硬事实；契合看语义覆盖；职业包不膨胀成主引擎。**
