# career-lens 项目说明书（v0.3）

> 求职者侧浏览器扩展：在 Boss / 猎聘 / 智联粗筛结果上做本地精筛。  
> v0.3：硬门槛门禁 + 契合四维（语义/向量优先）+ 规则/可选 AI 侧写；无模型时链路仍可走通。  
> 本轮增量见 [CHANGELOG.md](./CHANGELOG.md)。

---

## 1. 产品定位

| 项 | 说明 |
|----|------|
| 名称 | career-lens |
| 用户 | 各行业求职者（引擎通用；职业包可扩展） |
| 一句话 | 粗筛之后，按可验证事实做门禁 + 契合分析，输出可行动结果 |
| 形态 | Chrome / Edge 扩展（MV3），无自建后端 |
| 模型 | 用户自备 Key（可选）；单选多家 LLM |
| 不做 | 自动投递、自动打招呼、绕过验证码 |

## 2. 匹配主逻辑（v0.3）

```
简历 → 事实表 + 侧写（规则必跑 / AI 可选）→ 用户锁定
岗位 → 事实表（必须/优先）→ 断言 PASS/FAIL/UNKNOWN → 门禁
门禁 FAIL → 展示「硬门槛未过」+ 契合分封顶；不得建议投递；不自动收藏
门禁 PASS → 契合四维（语义/向量优先）→ 建议 / 谨慎
高契合被压分或规则分偏低 → 「待复核」（防漏，见 §2.3）
推荐状态不可信（无可用模型结论等）→ 「待复核」，不得「建议投递」（见 §2.6）
详情未真正加载（失败页/页脚噪声）→ 不打分入库，暂停重试（见 §6）
LLM 岗位解读 → 只解释，不改分、不改门禁（按契合原分比分析阈值）
```

### 2.1 门禁（Quality Gate）

| 项 | 约定（已确认） |
|----|----------------|
| UNKNOWN（如 JD 要英语工作语言、画像未填语言） | **按 FAIL**（严） |
| 门禁失败展示 | 主标签「硬门槛未过」，旁注封顶前契合分 |
| 封顶分 | `min(契合分, 35)` |
| 「建议投递」/ 自动收藏 | 门禁未通过时禁止 |

门禁覆盖：必须证书、必须语言、必须年限（规则）；领域由语义分偏低触发（有 Key 时），无 Key 时职业包词表兜底。

### 2.2 断言形态

硬事实断言（证书/年限/语言）由**代码对字段执行**。  
领域/角色/能力由语义相关性打分，不再靠「每个岗位一个大词表」代替。

### 2.3 待复核（防漏召回）

假阴性比假阳性更伤：分打低了会漏掉好岗。在「建议 / 谨慎 / 已排除」之间增加 **待复核**：

| 触发（未避雷） | 条件 |
|----------------|------|
| 高契合被门禁压住 | `gate FAIL` 且（域压分前）契合分 ≥ **60**；或角色高+能力尚可的跨域近邻 |
| 门禁过了但展示分偏低 | `gate PASS` 且展示分 < 60 且契合分 ≥ **60**；或方向词命中标题且契合分 ≥ **55** |
| 推荐状态不可信 | 见 §2.6（有 Key 应分析却无模型正文等） |

| 动作 | 建议投递 | 待复核 | 谨慎 | 已排除 |
|------|----------|--------|------|--------|
| 自动收藏 | 门禁过 + 达收藏阈值 | 否 | 否 | 否 |
| 调 AI | 按 **契合原分** ≥ 分析阈值 | 同左 | 同左 | 否 |
| 投递列表 | **契合原分** ≥ 入库阈值 | 同左（可含门禁 FAIL） | 同左 | 否 |

分组顺序：建议投递 → **待复核** → 谨慎投递 → 已排除。

### 2.4 JD 具体度（防空岗虚高）

任职多为软素质套话、职责过短、无行业/技术硬要求时，**JD具体度**偏低：中性维不再给满分，总分缩放并封顶，且不得「建议投递」。  
Boss 正文需去除汉字间插入的「直聘」噪声，否则「漫剧」等职责域词会抽不出来。

### 2.5 需求单元与覆盖率

- **或选**：`精通 A、B、C 至少一种` / `熟悉 A 或 B` → 一个单元，命中任一即满足。  
- **能力分** ≈ 已覆盖单元 / 全部单元（相对岗位需求的简历覆盖程度）。  
- **福利 chips**（五险一金等）不进入必备缺口。  
- **PM 过程隐含**：有项目经理 / PMP / 项目管理背景时，评审会、资料归档、交付复盘、会议纪要等常见过程动作视为已覆盖，不因简历未写字面词记缺口。  
- **软缺口不挡建议**：信息化/数字化近义、瀑布/敏捷等字面未写但背景可覆盖的项进 `softGaps`，不强制「谨慎」。

### 2.6 列表预筛（不开详情）

- **标题强跨域**（芯片/半导体/电力/医院/马拉松/土建等专业词，且标题无信息化/软件/系统等软化词，画像亦无该域）→ **已排除**，三平台均跳过开详情。  
- **列表避雷命中** → 已排除，跳过开详情。  
- 节奏：每开详情 5 次额外休息 1–3s；每随机 8–12 次列表滚动/停顿；猎聘另有更长条间隔。  
- **日限额（软锁）**：今日平台风控 ≥3 次，或猎聘开详情 ≥25 → 精筛禁用至次日（本地计数，清扩展数据会重置）。  
- 首次精筛须勾选使用须知。

### 2.7 推荐状态可信度（有 Key 时）

假阳性「建议投递」会浪费投递机会。约定：

| 项 | 约定 |
|----|------|
| 何时允许「建议投递」 | 门禁通过、非稀疏 JD、硬缺口不挡，且（无 Key 纯规则 **或** 已有模型分析正文） |
| 已配置 Key 且 ≥ 分析阈值 | **必须有模型分析正文**；否则一律 **待复核**，即使规则四维满分 |
| 不可信来源（不限错误码） | 模型 503/429/网络失败/空响应、语义降级后退回规则虚高、失败详情未加载 |
| 瞬时失败 | LLM 请求自动退避重试（约 3/8/15s，最多 3 次）；仍失败 → 待复核并继续下一条 |
| 无 Key | 仍可按规则分建议/谨慎（纯本地模式） |
| 导出提示 | 待复核且状态不可信时标明「勿信规则虚高分」 |

## 3. 简历侧写

| 项 | 约定 |
|----|------|
| 规则轨 | 上传/提取后**必跑**，产出有实质内容的分析（角色倾向、能力归纳、行业轨迹、资质、语言状态、适合/慎投方向），非三行摘要 |
| AI 轨 | 用户点击「生成 AI 侧写」；有 Key 时生成更完整叙述与归类建议 |
| 无 AI | 规则侧写完整可用；提示可配置模型增强 |
| 锁定 | 保存画像即作为后续匹配用画像（侧写结果一并存储） |

## 4. 职业包（通用化）

- 引擎不写死个人；**职业包**提供适合岗位类型列表，以及无 Key 时的域词兜底。  
- **MVP 职业包**：`it-delivery-pm`（软件/IT 交付型项目经理）。  
- 侧栏展示：当前包适合分析的岗位类型。  
- **主打分不靠包内大词表**；领域/角色/能力以语义相关性为准。  
- 禁止在核心打分里堆个案词；个案进包或由通用句式抽取。

---

## 5. 契合四维（语义/向量优先）

面向**所有岗位**，边界按大众语义：

| 维度 | 默认权重 | 大众理解 |
|------|----------|----------|
| 角色契合 | 25 | 这活是干什么的，和你想做/做过的是否一类 |
| 领域契合 | 30 | 行业/业务场景是否同域（金融 vs 土建 vs 短剧…） |
| 能力契合 | 30 | 方法、工具、技能是否覆盖职责 |
| 资质条件 | 15 | 证书/年限/语言等条件贴合（硬事实仍先走门禁） |

**打分来源：**

1. 有 API Key：**语义相关性**（OpenAI/通义 embedding 余弦；DeepSeek 等 LLM JSON 四维）  
2. 无 Key：规则映射 + 职业包词表仅作领域兜底  

门禁 FAIL 时展示分封顶。避雷 / 注意行为不变。

## 6. 批次、平台、导出、暂停与存储

- 平台：Boss / 猎聘 / 智联（URL 识别）。  
- **猎聘**：分页翻页；详情后台新标签采集；条间隔更长以防风控；进短信验证页立即暂停（须手动继续）。建议本批 ≤5。  
- **Boss**：下拉加载；条末短补间隔。  
- **列表预筛**：标题强跨域 / 避雷 → 跳过开详情（见 §2.6）。  
- **详情质量**：正文含「数据加载失败」、页脚「热门职位/求职工具 VIP」等 → 视为未加载成功，**不打分**，暂停后约 10 秒自动探测并重试当前条（请先刷新详情/列表）。  
- **暂停恢复**：验证码 / 网络异常 / 切走标签页 → 系统暂停并约每 10 秒自动探测；**手动暂停**与猎聘短信风控需点「继续运行」。  
- **日限额**：风控 ≥3 或猎聘开详情 ≥25 → 精筛软锁至次日；首次须同意使用须知。  
- 导出：MD / Word；投递列表 **xlsx**（冻结表头）。  
- 存储：`unlimitedStorage` + 断点压缩；若见 `kQuotaBytes quota exceeded`，点「从头」或清除扩展数据（见 [TECH.md](./TECH.md)）。

## 7. 验收（v0.3 MVP）

1. 「持有一级机电建造师」且画像无证 → 硬门槛未过、分封顶、不收藏、不得建议投递  
2. 同上场景若契合原分较高（≥60）→ 分入「待复核」，可调 AI、可进投递列表  
3. 「英语可作为工作语言」且画像无语言 → 门禁失败；高契合则待复核  
4. 无模型时可生成规则侧写；有模型可点「生成 AI 侧写」  
5. 画像页可见职业包及适合岗位类型  
6. 投递列表可导出 xlsx（冻结表头、列宽自适应）  
7. 「精通 ERP、OA 至少一种」且简历仅有 ERP → 该单元视为满足，不因缺 OA 记三个缺口  
8. 有 PM 背景时，「评审会/资料归档」不进必备未满足  
9. 无自动投递  
10. Boss 详情「数据加载失败」+ 页脚热门职位 → 不入库「建议投递」，暂停/重试  
11. 有 Key 时模型失败（含 503）或仅规则满分 → 进「待复核」，不得「建议投递」  
12. 系统暂停后刷新列表页 → 约 10 秒内可自动继续（手动暂停除外）
